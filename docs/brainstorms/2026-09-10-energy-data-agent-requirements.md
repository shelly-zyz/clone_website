# 能源数据理解、可信问数与分析智能体

## Problem Frame

项目不应把AI能力简化为“报表上增加一个聊天窗口”。如果用户的问题经过大模型直接生成SQL，系统可能选错表、混淆单位和数据身份，或把缺失数据编造成看似完整的答案。小红书“数问台”的有效启发是把数据库理解、业务语义和分析资产复用放到问数之前和之后；本项目还需要保留EnergyIR/GeoIR的空间语义、确定性编译、只读权限和真实数据边界。

目标是建设一个从“数据理解”到“可验证分析”的能源智能体。SQL只是受控工具之一，不能成为唯一的产品中心。

## Requirements

**数据理解与语义资产**

- R1. 系统应基于数据库结构、数据目录、字段统计、来源和已有API生成可审核的字段含义、关联关系和指标候选。
- R2. AI提出的语义只能作为候选，经过人工或规则审核后才能进入正式语义资产；不得把模型猜测直接当成业务口径。
- R3. 每个正式指标必须记录来源、单位、时间范围、空间粒度、数据身份、缺失状态和版本。
- R4. 语义资产应区分真实观测、官方统计、正式预报、研究估算和模型情景，禁止跨身份混算或改写标签。

**问题理解与受控执行**

- R5. 用户问题应先转换为EnergyIR/GeoIR分析计划，至少表达意图、地区、设施、指标、时间、数据身份、分组、图表和可用性要求。
- R6. 系统必须先进行实体Grounding、指标校验、权限检查和数据可用性检查，再决定调用指标API、空间查询、气象/碳接口、预测接口或其他工具。
- R7. 第一版不允许大模型生成的自由SQL直接执行；执行只能经过白名单、只读权限、确定性编译、超时和结果规模限制。
- R8. 对缺数据、口径冲突、时间含义不清或超出支持范围的问题，系统应明确拒答或要求澄清，不能生成假值。
- R9. 查询结果必须在展示前检查单位、时间、数量级、来源、更新时间和缺失状态。

**分析交付与复用**

- R10. 回答应同时提供表格、地图或图表、来源、单位、数据身份、时间范围和限制说明；文字解释只能引用已验证结果。
- R11. 通过审核的分析应保存为带版本的分析配方，后续可以替换省份、技术、时间或图表参数而不重新发明口径。
- R12. 第一批应建立30—50个允许、缺失、歧义和拒绝类金标准问题，用于回归测试；其中首批薄切片至少覆盖能源设施/来源、数据集质量状态、GFS/GRACED/VRE/OSM图层可用性三类问题。
- R13. 分析师对字段、口径或答案的修正应进入待审核反馈记录，不能自动覆盖正式语义资产。

**后续扩展**

- R14. 预测、调度和碳计算问题应路由到各自的受控业务服务，不要求所有问题都转换成SQL。
- R15. IM渠道和全双工语音只能复用同一文本智能体，不得绕过Grounding、权限和结果验证。

## Success Criteria

- 30—50个金标准问题能够稳定区分允许、缺失、歧义和拒绝场景。
- 支持的问题能正确绑定地区、设施、指标、单位、时间、数据身份、分组、图表和可用性要求。
- 所有答案均可追溯到数据源、接口或已审核分析配方。
- 写入、删除、更新和越权查询在执行前全部被拦截。
- 相同分析配方更换省份、技术、时间或图表参数后，口径和图表结构保持一致。
- 没有真实数据标签的问题会显示不可用，不输出伪造预测或官方统计。

## Scope Boundaries

- 第一版不是通用数据库管理员，也不自动修改表结构、字段注释或业务口径。
- 第一版不开放任意SQL、任意Python、写入数据库或自动执行数据清洗。
- 第一版不负责补齐省级小时负荷、真实风光功率、调度参数或排放因子。
- 飞书、企业微信、钉钉和语音不属于第一版智能体核心功能。
- 论文中的GeoIR基准分数和私有数据不可声称被复现。

## Key Decisions

- **采用“数据理解＋可信问数＋图表分析＋模板复用”**：吸收帖子中语义治理和资产复用的有效部分，同时保留本项目的空间数据与真实数据约束。
- **保留EnergyIR/GeoIR作为安全中间层**：大模型生成结构化分析计划，程序负责确定性执行和验证。
- **把语义契约前移到中国大屏API阶段**：接口建设时就记录指标、来源、单位、时间范围、空间粒度、数据身份、缺失状态和版本，避免第八步再返工。
- **SQL降级为受控工具**：高频问题优先使用指标API和固定空间模板，长尾SQL以后只能进入受限分析师模式。
- **首版用户确定为能源数据分析师/项目分析人员**：他们能够审核数据口径，也最需要减少查表、对字段和核验来源的重复劳动。
- **首版问题确定为三类薄切片**：能源设施与来源查询；数据集时间范围、更新时间和缺失状态查询；GFS、GRACED、VRE、OSM图层可用性与覆盖查询。

## Dependencies / Assumptions

- 中国大屏只读API契约已经稳定，并能返回来源和不可用状态。
- 数据目录和数据库字段级质量信息持续更新。
- PostgreSQL/PostGIS、天气、碳和VRE接口可以提供稳定的只读查询。
- 预测问题只有在真实功率标签和历史NWP通过数据门禁后才开放。

## Outstanding Questions

### Resolve Before Planning

- 无。首版用户和三类优先问题已由用户确认。

### Deferred to Planning

- [Technical] 首批30—50个金标准问题的具体分组和覆盖比例。
- [Technical] 语义候选的人工审核界面及版本发布流程。
- [Needs research] 选择本地模型、云模型或混合模型时的成本、隐私和延迟边界。
- [Technical] PostGIS是否需要先补充原生geometry/geography字段和空间索引。

## Next Steps

将三类首批问题映射到中国大屏现有只读API的指标和数据身份，整理语义契约，随后进入EnergyIR/GeoIR的结构化分析计划、路由和金标准问题设计。完成详细技术规划后再实现代码。
