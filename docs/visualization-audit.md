## 引擎和 Skill 来源

- Microsoft Flint 采用 MIT。GitHub 已发布 1.1，审计时 npm 可安装的 `flint-chart-mcp` 最新版本为 `1.0.1`。固定该版本，运行时用 `tools/list` 核对编译与校验。项目的 Pi 客户端没有 MCP Apps 的宿主界面，结果使用现有图表画布。第三方仅通过本地进程接收受控行数据。 [官方发布](https://github.com/microsoft/flint-chart/releases/tag/1.1) · [MCP 接口](https://github.com/microsoft/flint-chart/blob/main/packages/flint-mcp/README.md)
- Academic Figure 采用 Apache-2.0。审计代码点为 `1df9940`。采用其按研究问题选图、栏宽和矢量交付思路。项目固定 Python 渲染器接收已验证的绘图数据。 [上游规范](https://github.com/TingxiYu/academic-figure-skill/tree/1df9940dd01ac939f072b12fe28d6353b79b90f9)
- Apache ECharts 采用 Apache-2.0，项目已固定 6.1.0。适用普通交互图和多面板布局。需要规则网格三维曲面的任务才选 MIT 的 Plotly GL3D。 [ECharts 发布](https://github.com/apache/echarts/releases/tag/6.1.0) · [Plotly Surface 接口](https://plotly.com/javascript/reference/surface/)
- Vivid Illustration 在 `7adbe09` 的许可限制二次开发与商业使用。本项目只参考公开说明中的分类和审图方法，采用原创的图型配置、色板和布局。 [上游许可说明](https://github.com/yjz211/vivid-illustration-skill/tree/7adbe09d3d08c55a51733d3b1268fe54f7689559)

待验证的主要风险是区间口径、跨来源对齐、服务部署时的字体和隔离、编译配置是否改写数据，以及旧请求和新图件修订之间的权限边界。验收使用固定输入、真实发布数据和浏览器交互分别验证。

## 方案适配性结论

多 Skill 分工、发布数据溯源、预测结果复用、可重开的图件版本和阻断式校验都适合现有项目。主要冲突集中在跨专题授权、多个渲染器的边界、图件版本存储和目前的数据覆盖。建议将总管设计为**科研制图工作区的唯一规划入口**，并保留小云的常规问数、单指标出图及打开已有页面的入口。是否进入科研制图，由动作和交付目标决定。

| 原方案设计 | 现有约束与实测 | 调整建议 |
| --- | --- | --- |
| 单次任务按需加载多个领域 Skill | 小云一轮只允许 `bind(topic)` 一次。会话与项目按专题保存，`resolveDataResult` 同时验证结果、项目和密钥。直接在一轮里对两个专题连续调用旧 `query_data` 会被拒绝。 | 在科研工作区单独校验各输入的授权。同一授权下解析已经发布的跨领域指标。引用其他项目的既有结果时，先核验该项目对源结果的访问权。用地区、时间粒度、时区、有效时间和口径做配对，拒绝把空间尺度不一致的结果直接相关。 |
| 每个步骤都加载 Skill 并调 MCP | Pi 总管有 7 次模型调用和 9 次工具调用上限，父子流程共享预算。逐个让模型加载、比选、校验四类 Skill 会占用问数和追问预算。 | Pi 提交一次受约束的意图或修改请求。程序用已授权的数据反查领域并挑选 Skill。同一职责只分配一个执行者。领域工具返回规范化数据和事实，主题只输出样式。Data Storytelling 负责已验证结果的文字组织。 |
| 优先级要求同时强调用户指令和领域规则 | 用户明确指定图型，也可能要求让总量用速率替代，或让预测点值显示置信区间。必须同时检查口径、权限和必要输入。 | 第一层固定检查权限、物理口径和可验证数据。符合条件的用户指定图型和渲染器优先；其后取领域推荐、引擎能力与默认主题。无兼容方案时用明确错误或可选图型。 |
| Flint、ECharts、Python、Plotly 共同制图 | 已有 ECharts 支持多数站内图型，Three.js 和地图负责专业场景。Flint 是规格编译器，编译后的图仍由 ECharts 渲染。现有 Pi 宿主没有挂载 MCP App 的前端。 | 路由分开记录编译器和最终渲染器。首次以 ECharts 作为大部分交互图的渲染器。只有任务确实需要 Flint 语义规格时调用 Flint，先验证、再编译、再对账。Flint 的 `show` 不接入现有容器，Plotly 在出现专用组件无法覆盖的已发布三维网格需求时评估。 |
| 论文工具、自动视觉验证和多格式导出 | 默认 Node standalone 镜像复制预测 Worker 脚本。Python 科研制图及中文字体需要独立运行环境。现有 CSV 编辑器能导出浏览器 PNG/SVG，论文出图还需栏宽和字体控制。 | Matplotlib 在受限的工作进程中消费固定模板和数据模型。记录字体、栏宽、DPI 和工具版本。版式检查结合渲染的尺寸、标签溢出检测和浏览器截图。按引擎申明 PNG、SVG、PDF 能力。 |
| 依靠现有会话完成任意版本回放 | `projects.agent_session.recent` 只保留最近四轮。最近记录随对话更新会被挤出，不能充当持久版本库。 | 保存独立图件 ID、不可变修订、数据版本与查询键、转换顺序及引擎版本。复用现有项目授权和事务并发规则。改主题、字体或布局只改变图件配置，重开原修订仍读取原来的数据和分析任务。 |

| 用 Vivid 快速覆盖大量图型 | 上游明确约束商业使用和二次开发。图型分类适合参考，科研主题和已有组件已足够实现第一批图。 | 用原创配置实现多面板组合和审图规则，正式站点交付使用项目可分发的资产。 |

## 实测边界

- 以本地 stdio 启动 npm `flint-chart-mcp@1.0.1 --disable-file-reference`，成功获取工具清单。清单含 `list_chart_types`、`validate_chart`、`compile_chart`、`get_flint_skill` 与 `show`。对 ECharts 线图的 `validate_chart` 返回 `valid: true`，`compile_chart` 生成可读的系列和轴。带空值、零和负值的唯一年份样例保留原值。将两条不同观测绑定同一年份而不提供区分字段时，编译成功但只保留第一条。因此出图前要检查唯一键，编译后检查类别、数值和缺测掩码。 [Flint MCP 官方说明](https://github.com/microsoft/flint-chart/blob/main/packages/flint-mcp/README.md)
- 版本与依赖按运行环境登记。当前核验只覆盖本地 Flint MCP 的编译和校验。多面板渲染、独立 Python 部署、导出字体回归、工作区持久化和全量浏览器场景属于后续验收。
- 外部候选数据应保留实际覆盖与许可。ENTSO-E 面向欧洲市场；Copernicus CDS 按所选产品区分再分析与预报；EDGAR 和 Carbon Monitor 的时间粒度、排放口径各异。FRED、IMF、World Bank 按具体指标核对来源、修订和许可。 [ENTSO-E](https://transparency.entsoe.eu/) · [Copernicus CDS](https://cds.climate.copernicus.eu/) · [EDGAR](https://edgar.jrc.ec.europa.eu/) · [Carbon Monitor](https://carbonmonitor.org/) · [FRED](https://fred.stlouisfed.org/) · [IMF Data](https://data.imf.org/) · [World Bank Data](https://data.worldbank.org/)

## 建议实施顺序

1. **打通 ECharts 的可复现工作区。** 首批覆盖风光月度电量、GFS 多指标、GRACED 排放速率、WDI/GEP 历史及展望。统一数据契约、确定性 Skill 路由、受控局部编辑和独立图件版本。在已有 `/visualization/[topic]/custom` 交付，保留手工入口与原业务路由。
2. **接入科研导出和 Flint。** 先验收一个 Matplotlib 矢量多面板配方和一个 Flint → ECharts 的对账配方。用同一图件编号复现尺寸、样式、数据来源和预测参数，再扩展统计图型。将验证与渲染排在保存前，质量验证失败继续保留上一份可用图件。
3. **以真实数据拓展难例。** 由发布服务登记负荷、电价、碳情景和可对齐的气象数据。补齐测试后再扩展对应领域工具，三维曲面由现有组件和 Plotly 的实测覆盖决定。

第一轮验收建议同时具备一条完整用户操作链、四类经核对来源的数据，以及权限与缺测的反向用例。发布覆盖不足的研究问题应单列为数据任务，固定样例只能用于算法和界面验收。
