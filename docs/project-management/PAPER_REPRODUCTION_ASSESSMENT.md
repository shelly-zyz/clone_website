## 一、动态匹配与在线建模的超短期风电预测

### 论文

- 标题：*Ultra-Short-Term Wind Power Forecasting Based on the Strategy of “Dynamic Matching and Online Modeling”*
- DOI：https://doi.org/10.1109/TSTE.2024.3424932
- IEEE文档号：10620613

### 公开代码核验

- 论文正文和本地全文抽取中没有GitHub、代码仓库或Data/Code Availability链接。
- 以完整标题、DOI、`GADF_D`、作者和方法关键词检索，没有找到与该论文直接对应的官方仓库。
- GitHub仓库搜索中虽然存在其他“超短期风电预测”项目，但没有仓库包含该论文DOI，不能当作作者代码。
- 三个中国风场的一年15分钟数据为非公开运行数据。

### 正确理解论文流程

论文不是“KNN提取特征”，实际流程是：

1. 用PAA压缩历史功率序列和未来NWP风速序列；
2. 归一化后编码为Gramian Angular Difference Field（GADF）二维图像；
3. CNN输出128维波动特征；
4. K-means对特征聚类并生成伪标签，CNN使用伪标签迭代训练；
5. 对功率波动特征、NWP波动特征、原始功率幅值和原始NWP幅值分别计算欧氏距离；
6. 归一化、加权后选择距离最小的500个历史样本；
7. 用500个样本在线训练LSTM Seq2Seq，预测未来4小时的16个15分钟点。

论文正文存在一个重要矛盾：公式说明“距离越小越相似”，但文字一处写成降序取样。正确实现应按距离升序选择，并通过单元测试固定该规则。

### 各工具是什么、为什么适合、何时用和限制

- **GADF**：把一维时间序列转换为二维角度关系图；解决“只比较数值、难表达波动形态”的问题；适合项目展示相似风过程；在真实序列清洗和窗口切分后使用；限制是图像化增加计算量，且论文公式/文字有可疑点，必须自行校对。
- **CNN**：从GADF图像中提取128维特征；解决手工均值、方差难以描述复杂波动的问题；适合批量离线生成特征库；在样本量足够后训练；限制是可解释性较弱，数据不足时可能不如DTW。
- **K-means/DeepCluster**：用聚类结果作为CNN伪标签；解决没有人工波形标签的问题；适合无监督特征学习；在离线特征训练阶段使用；限制是聚类数、初始化和收敛规则未完整公开，结果可能不稳定。
- **欧氏距离/Top-K检索**：计算当前场景与历史场景的距离并选样；解决全量训练慢、混入无关场景的问题；适合每次预测前选择局部样本；在特征标准化后使用；限制是必须按训练窗口拟合归一化，历史库大时需FAISS/HNSW加速。
- **LSTM Seq2Seq**：用精选样本现场训练多步预测器；解决概念漂移和多步输出问题；适合15分钟到4小时预测；在样本匹配后后台异步运行；限制是论文约30—40秒的耗时不能直接承诺，在线重训需要超时、回退和版本管理。

### 推荐实施顺序

1. 先实现持续性、前一天同刻、功率曲线/LightGBM等基线。
2. 实现不依赖深度学习的`z-normalized Euclidean/DTW + 近邻加权`版本。
3. 取得真实数据后比较“全量LightGBM、近邻LightGBM、在线LSTM”。
4. 简化匹配稳定获益后再加入GADF/CNN/K-means。
5. 大屏只显示真实回测后的模型；在线失败回退到已验证基线并明确标识。

## 二、GeoIR-Compiler与项目EnergyIR/GeoIR智能体

### 论文

- 标题：*GeoIR-Compiler: A Geospatial Intermediate Representation and Compilation Framework for Chinese Urban Spatial Question Answering*
- DOI：https://doi.org/10.3390/ijgi15070310
- 正式论文：https://www.mdpi.com/2220-9964/15/7/310

### 公开代码核验

- 论文Data Availability Statement称：审稿包通过匿名OSF链接提供；接受后计划公开基准、脚本、Schema和文档。
- 正文没有给出可公开访问的仓库URL、OSF记录ID或归档DOI。
- 以`GeoIR-Compiler`、`WH-GeoIR-700`、`NJ-GeoIR`和作者信息检索，未找到公开GitHub仓库或对应公开OSF记录。
- 因而当前无法下载作者代码，也无法复跑论文报告的武汉/南京基准分数。

### 我能否复现智能体

可以实现面向本项目的EnergyIR/GeoIR智能体，而且项目范围比论文城市开放问答更窄，更适合采用确定性实现：

```text
用户问题
→ LLM只生成EnergyIR/GeoIR JSON
→ JSON Schema类型校验
→ 地区、设施、指标、时间和单位Grounding
→ 权限与数据可用性检查
→ 确定性编译为只读API/PostGIS查询
→ 结果范围、单位和来源验证
→ 地图/表格/曲线
→ LLM根据真实结果解释
```

### 各工具是什么、为什么适合、何时用和限制

- **EnergyIR/GeoIR**：用户问题的结构化中间表示；解决大模型直接写SQL容易查错、越权的问题；适合本项目固定的能源指标和空间关系；在任何AI查询执行前使用；限制是必须维护类型、枚举和版本。
- **Grounding**：把“中国、广东、风电装机、昨天”等语言绑定到标准ID、字段和时间；解决同名、别名和口径歧义；适合省份、设施和指标查询；在编译前使用；限制是别名库和数据目录不完整时必须拒答或澄清。
- **JSON Schema校验**：检查IR字段类型、必填项和允许值；解决模型输出格式漂移；适合所有工具调用；每次LLM输出后立即使用；限制是只能保证结构合法，不能保证问题理解正确。
- **确定性编译器**：由程序模板把合法IR转换为只读SQL或API参数；解决自由SQL不可控的问题；适合高频、可枚举的能源问题；在权限检查后使用；限制是覆盖不到的长尾问题需要新增模板，不能擅自自由执行。
- **PostGIS**：PostgreSQL的空间扩展；解决包含、相交、距离和最近邻等地图查询；适合行政区、设施和线路；在本地数据库重建后使用；限制是当前云库不可用，且现有Schema还没有完整原生geometry/geography迁移。

### 项目复现边界

- 可以复现：IR结构、校验器、Grounding、确定性编译、只读执行、安全限制、结果验证、30—50个金标准问题。
- 不能声称复现：论文私有/未公开基准、原始数据库快照、作者提示词与报告准确率。
- 实施前提：先恢复本地PostgreSQL/PostGIS，完成数据资产目录和稳定只读API。

## 三、最合理优先级

1. 先重建本地数据库并恢复真实数据API。
2. 中国大屏先实现真实地图、来源和数据质量组件。
3. 获得真实15分钟功率与历史NWP后，实现超短期预测基线及动态匹配原型。
4. 在稳定数据API上实现EnergyIR/GeoIR智能体。
5. 最后才接入语音；语音只复用同一受控智能体，不另建业务逻辑。
