# 预测与回测

## 先确定用户要做什么

- **看已有预报。** 用户指定 GFS 或要求查看已发布的天气预报时，用 `query_data` 查预报帧，或用 `inspect_data` 读已选结果。按有效时间展示，说明起报时间。需要趋势图时用 `render_chart`。
- **预测未来。** 用户明确要求用历史数据外推时，选择 `forecast`。先定位已有历史结果，或让 `query_data` 查对应的历史观测。预报帧只能用于展示或描述。如果目录只有预报帧，说明当前缺少历史输入。
- **用已知历史评估。** 用户要求留出已发生的时段验证时，选择 `backtest`。用户要求把指定模型与基线比较时，选择 `compare`。在相同输入和留出窗口下解释结果。

## 先检查方案，再提交

1. 用 `inspect_data` 传入目标和 `plan`。预测期数与数据粒度相符时才提交。例如月度结果的一期对应一个月。用户要求三天时，检查是否有日度结果。
2. 从回执的 `forecastModels` 选择。用户指定模型时保留选择；未指定且 StatsForecast 可用时优先用它。服务会返回预检原因，例如时间不连续、留出窗口太长、模型未启用。
3. 预检通过后用同一目标和方案调用 `submit_analysis`。预检拒绝时使用工具给出的实际范围和可选调整。需要补查时以被引用的结果为基准，只改历史时间范围。先让用户决定缩短留出窗口或扩大范围，再提交调整后的任务。
4. 用户修改旧预测的模型或期数时，用 `target=analysis` 保留该任务的数据与未改参数。查看任务状态用 `get_analysis`。入队后按真实状态汇报，并让结果卡提供数据版本和计算结果。
